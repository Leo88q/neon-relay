## 2. Предлагаемый дизайн-язык: «Potato Arena Night Drive»

Одна формула для всего: **объёмный мультяшный 2.5D (как портреты `data/portraits/`) + ночная
неоновая подсветка Night Drive**. Портреты — самая сильная часть проекта, поэтому стиль тянется к ним,
а не наоборот.

Правила (жёсткие, применимы к любому генератору/художнику):

- **П1 Палитра.** Только токены §1.1 + два rarity-акцента: `#A077FF` (rare), `#FFC857` (legendary).
  Запрещены: чистый синий `#0000FF`, оранжевый фон кошелька, зелёный кроме семантики «здоровье».
- **П2 Семантика.** `cyan = безопасно/доступно`, `pink = урон/риск/таймер` (уже закон §DESIGN_SYNTHWAVE).
  Золото = только награда/легендарка.
- **П3 Техника одна.** Мягкий 2.5D: объёмная форма, один источник света, glow 8-24px, лёгкий шум
  2-3%, без «фото-реализма», без пиксель-арта, без wireframe blueprint.
- **П4 Никакого текста в растре.** Псевдо-буквы (см. `settings_grid.png`) запрещены: подпись всегда
  рисуется шрифтом клиента. Негатив-промпт обязателен: `no text, no letters, no watermark, no UI panels`.
- **П5 Персонаж не дублируется.** Фон не содержит персонажей/картошек: они рисуются клиентом
  (`RenderCharacterPortrait`), иначе будет «двойная картошка».
- **П6 Тихая зона.** Левая 45% и нижние 120px фона — низкая яркость (L ≤ 40), правый верх —
  «герой» кадра. Плюс общий диммер в `RenderBackground`: `night-0 @ 55%` + вертикальный градиент
  к низу (реализуется 3 квадами, без ассетов).
- **П7 Толщина/радиус.** Единая сетка: скругление панелей 16px (Form A), карточка 12px, бордер 2px,
  glow 10px 30%. Отступления только по rarity (у legendary импульс 6s вместо 5s).
- **П8 Иконки — один лист.** Геймификация и категории оружий рисуются на одном листе 64px,
  оптический вес 4px, скос 45°, внутренний glow, общий bbox 56×56 внутри 64×64.
  Font Awesome остаётся для служебных UI (настройки/браузер/демо) — mixing запрет: на одном экране
  либо FA-глифы, либо PNG-атлас, не вперемешку в одном заголовке.
- **П9 Честность.** Копирайт-риск и запрет обещаний дохода (см. `docs/REWARD_SECURITY.md`,
  `docs/RELEASE_CHECKLIST.md`) распространяется на геймификацию: XP/уровень/квесты помечаются как
  «локальный прогресс», никаких «гарантированных выплат». Формулировки вида «ты заработаешь» запрещены.

Форматы: PNG RGBA; фоны 1920×1080 → целевой вес ≤400 KB/файл (проверка в `scripts/check_assets.sh`
расширяется gate'ом); иконки 64px (атлас) и 256px (оружие, source `assets-src/`).

### П4 — геймификация меню (три уровня зрелости, выбираем объём)
Локальный слой (считает клиент, ничего не обещает):
- `src/game/client/neon_progress.h/.cpp`: счётчики `matches, kills, deaths, wins, best_streak,
  burn_survived, xp`, персист — новые `MACRO_CONFIG_INT(..., CFGFLAG_CLIENT | CFGFLAG_SAVE)` в `src/engine/shared/config_variables.h` (как остальной клиентский конфиг базовой игры), отдельный файл не нужен.
- Формула уровня: `xp_for_level(L) = 250 * L * (L + 1) / 2` (L=1..30, дальше plateau) —
  детерминированная, легко тестируется; в UI показывается «локальный прогресс».
- Ежедневный квест: 3 слота из детерминированного пула 12, ключ дня = `YYYYMMDD` (hash → 3 индекса),
  награда — XP (не деньги). Недельный квест — 1 слот.

UI (в `menus_settings_wallet.cpp`, новые функции `RenderProgressPanel`, `RenderQuestRow`,
`RenderTierTrack`; точки вставки — `menus.cpp:1005-1030` + `RenderMenubar` `menus.cpp:551-582`):
1. **Tab-bar с иконками**: 5 вкладок = иконка 24px + подпись; активная — cyan-подчёркивание 3px +
   4px-чип статуса.
2. **HUD-чип игрока в шапке**: уровень (кольцо-прогресс) + XP-полоса + streak-флейм.
3. **Races/лобби выжигания**: карточка тира получает (а) полосу заполнения «12/16 бойцов»,
   (б) gauge «пул призов 90/10» (текст-лейбл обязателен, цифры из `RACE_CATALOG`),
   (в) строку из 6 иконок оружия с подсветкой доступных в этом тире,
   (г) чип «ticket 100 SKR»/«free».

## 7. Что осталось (следующие шаги, по убыванию ценности)

1. ✅ **`data/emoticons.png` + `data/gui_icons.png`** — перегенерированы в `scripts/build_neon_ui_art.py`
   плоским стилем из §2 П8 (толщина `ink(cell) = max(2, round(cell/16))`, у эмодзи — пластина с
   акцентной рамкой, как карточки меню). Сетка и имена слотов не менялись, `--check` остаётся валидным
   гейтом. См. пункт 4: попутно выяснилось, что листы не совпадали с сеткой спрайтов.
2. ✅ **`♥` в `chat.cpp` и `⬤`/`◯`/`♥` в `spectator.cpp` — сделаны спрайтами.** Глифы стояли
   внутри текстового потока (`CTextCursor`), поэтому замена обязана давать одинаковый сдвиг курсора
   и в измерительном, и в отрисовочном проходе: `CChat::FriendIconAdvance(FontSz) = FontSz * 1.15f`
   прибавляется к `MeasureCursor.m_X` ровно там, где раньше стоял символ, а `OnRender` рисует
   `RenderIcon(IMAGE_GUIICONS, SPRITE_GUIICON_HEART, ...)` в позиции, сохранённой для строки
   (`m_FriendIconPos`, `m_FriendIconSize = FontSize * 0.92f`, `m_HasFriendIcon`). Цвет приходит из
   `g_Config.m_ClMessageFriendColor`, поэтому настройка «цвет сообщения друга» не сломана. Символ
   больше не требует U+2665 в шрифте. В списке наблюдателя те же три места переведены на
   `DrawGuiIcon` с размером от `FontSz`. Проверяется `scripts/test_ui_sheet_grids.py` (киль в
   именованной клетке + «заливаемые» клетки чисто-белые) и побитовым `build_neon_ui_art.py --check`.
3. **`★`/`✰` рейтинга карт (`scoreworker.cpp:518-523`)** — остаются глифами осознанно: на них
   завязан регэксп `src/test/score_test.cpp:471-515`, а сама строка живёт в чате/скорборде, где
   спрайтов нет.
4. ✅ **Пред-существующий баг подтверждён и исправлен** (в том же подходе). `datasrc/content.py`
   объявляет `set_guiicons` сеткой 12×2 (ячейка 32px на листе 384×64), а спрайты остались от
   upstream-листа: `guiicon_mute (0,0,4,2)` и т.д. Единицы rect'а — **клетки**, а не пиксели
   (`set_game`: `weapon_hammer_body (2,1,4,3)` = 64,32,128,96 px), то есть кнопка 16px показывала
   128×64 px = сразу 4 иконки. У `emoticons` было хуже: сетка 4×4 на 512×512 = ячейка 128px, а
   генератор рисовал глифы с шагом 32px — каждый спрайт был мозаикой 4×4. `CheckImageDivisibility`
   проверяет только делимость размера на сетку, поэтому ни один gate не падал.
   Исправление: генератор объявляет разметку (`EMOTE_GRID/CELL/CELLS`, `GUI_ICON_COLS/ROWS/CELL/CELLS`),
   `content.py` выбирает ровно свою ячейку (`mute (5,0,1,1)`, `emoticon_mute (2,1,1,1)`,
   `friend (1,0,1,1)`), порядок 8 эмодзи совпадает с `SPRITE_OOP + i` в `gameclient.cpp`, а
   `scripts/test_ui_sheet_grids.py` (в `ci.yml` и `ci-local.sh`) сверяет обе стороны и требует чернил
   в каждой именованной ячейке. Листы перерисованы так, чтобы нужные движку иконки стояли на своих
   клетках; `--check` по-прежнему побитово воспроизводит оба PNG.
5. **Визуальная приёмка: частично закрыта CI.** В песочнице нет `cmake`/браузера, зато
   `Linux client build and desktop/portrait boot` собирает и запускает клиента под Xvfb — и первый же
   прогон поймал реальную регрессию: полоса прогресса в лобби сдвинула карточку, а
   `scripts/test_warmup_lobby.py` кликал по **вычисленной вручную** геометрии
   (`10+44+24+42+44+12+164-12-20`), то есть тест падал не на дизайне, а на своём предположении о нём.
   Теперь тест снимает rect кнопки с лога клиента (`practice-ui: ... button=(x,y,w,h)`) и кликает в
   измеренный центр: числа, которые гниют при любой правке лобби, из теста убраны. Скриншоты
