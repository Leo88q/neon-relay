# Операционная безопасность команды и казны (RU)

**Основание:** каталог инцидентов июня–сентября 2026, пункты **98–101, 105–107, 119–126, 128–130**
(Части 5–6 сводки). Этот документ — операционная половина защиты: код и on-chain-программы
закрыты тестами (`backend/test/tx_policy.test.ts`, `backend/test/rpc_quorum.test.ts`,
`backend/test/oracle_guard.test.ts`, `onchain/test/client_policy.test.ts`,
`scripts/check_key_provenance.py`, `scripts/check_supply_chain.py`), но атаки 2026 года в основном
шли **не через контракт**: ключи, подрядчики, IDE, домены, физическое принуждение.

Гейты, которые можно проверить командой, помечены `$`. Всё остальное — обязательства с ответственным.

## 1. Люди и подрядчики (§106, §123, §124, §125)

**Инциденты-основания.** WaterPlum/Contagious Interview (18.09.2026): ≥30 тыс. устройств, >7 тыс.
кошельков, ~$10,71 млн — фальшивые рекрутеры, «тестовые задания», подмена лица на интервью.
Meteora (17.01.2026, ~$1,5 млн) — фейковый OTC-эскроу. 10.01.2026 — ~$282 млн у одного держателя
после «поддержки Trezor». CertiK: 52 wrench-инцидента за H1 2026 (+33% г/г), 20 домашних вторжений.

| Правило | Как проверяем |
| --- | --- |
| Любой чужой код (тестовое задание, «партнёрский» репозиторий, патч от «инвестора») открывается **только** в `devcontainer`/одноразовой VM без ключей, `.env` и домашнего каталога | `.devcontainer/devcontainer.json` (§107) |
| VS Code Workspace Trust включён, автозапуск задач выключен: открытие папки не выполняет код | настройки в `devcontainer.json` + чек-лист ниже |
| Идентичность собеседника подтверждается по независимому каналу (видео подделывается); «инвесторы», «аудиторы» и маркет-мейкеры — через проверенных посредников | ручное, двойное подтверждение |
| Любая сделка **вне протокола** (OTC, выкуп, эскроу) — два разных человека, тестовая сумма, лимит, проверка адреса по независимому каналу | `tx_policy`: `offProtocolAlwaysDual = true`, `dualAboveMicro` |
| Казначейские ключи не лежат на рабочих ноутбуках руководителей; подписанты — разные устройства, вендоры, ОС и **города** | `$ python3 scripts/check_key_provenance.py` |
| Duress-протокол: заранее известно, кто и как сообщает «меня принуждают»; крупные выводы не может подписать один человек | порог мультисига ≥ 3, задержка на крупные переводы (`approval.delayAboveMs`) |
| Команда минимизирует публичные персональные данные (реестры компаний, WHOIS, соцсети) | квартальный аудит публичного следа |

**Правила для комьюнити (закрепить перед релизом):**

* официальная поддержка пишет **только** из перечисленных каналов и **никогда** не просит seed-фразу;
* модерация Discord/Telegram блокирует ссылки в личных сообщениях и предупреждает о «поддержке» в DM;
* закреплённое сообщение: «команда не пишет первой, не просит seed и не просит „переустановить кошелёк“».

## 2. Рабочее окружение и цепочка поставок (§99, §100, §107, §130)

**Инциденты-основания.** Ill Bloom (10.07.2026, >$5 млн) и SecondFi/Yoroi (23.06.2026, $2,4 млн
с 178 кошельков) — слабая энтропия ключей. Taiko (22.06.2026) — ключ подписи SGX в публичном
GitHub. 15 вредоносных плагинов JetBrains (июнь 2026) и ChainDrop через сотни npm-пакетов (август
2026). OpenClaw/ClawHub: 341–386 вредоносных навыков, Snyk оценил 36% навыков как имеющие изъяны;
навык может быть просто текстом-инструкцией без кода.

| Правило | Как проверяем |
| --- | --- |
| Ключи — только из проверенного CSPRNG или аппаратного кошелька; никаких самописных генераторов и vanity-грайндеров из непроверенных источников; у каждого ключа записаны устройство, прошивка, источник энтропии, дата, место | `$ python3 scripts/check_key_provenance.py [--file <manifest>]` |
| Ключи с затронутых прошивок (например, Coldcard < 5.6.0 из-за отката генератора на слабый software PRNG) считаются скомпрометированными и мигрируют; обновление прошивки уже созданные сиды не лечит | правило `known_bad_firmware` в манифесте, гейт выше |
| Секреты не попадают в репозиторий: pre-commit + CI + push protection; после любой утечки — ротация, даже если репозиторий был публичным недолго | `$ python3 scripts/check_secrets.py --self-test && python3 scripts/check_secrets.py` |
| Зависимости ставятся с `--ignore-scripts`, lock-файлы обязательны, у пакетов не может быть install-скриптов, релизные профили Rust собираются с `overflow-checks` | `$ python3 scripts/check_supply_chain.py --self-test && python3 scripts/check_supply_chain.py` |
| Расширения IDE и навыки/плагины ИИ-агентов — только из allowlist, с закреплением версии и хэша; агент с такими расширениями работает на машине **без** кошельков и `.env` | `.devcontainer` + правила ниже |
| Ключи ИИ-сервисов — в менеджере секретов, с лимитом расходов и минимальными правами (не в `.env`, не в `~/.npmrc`) | ревью конфигурации CI/секретов |

Чек-лист «машина разработчика»:

1. Диск зашифрован, вход по биометрии/паролю, отдельная учётка без admin-прав для сборки.
2. Кошелёк-подписант не установлен там, где открывается чужой код; аппаратный кошелёк — физически
   отдельно от рабочих машин.
3. IDE: включён Workspace Trust, запрещены автоматические задачи, плагины — из списка, который
   вы можете перечислить по именам и версиям.
4. Агенты (Claude/Cursor/иные) запускаются в контейнере без сети и без доступа к домашнему каталогу,
   если им передан внешний контент; их MCP-серверы проверяются как код.
5. После подозрения — отзыв и ротация **всех** ключей, к которым у машины был доступ, включая
   токены CI, RPC и облачные.

## 3. Домен, фронтенд и устройства игроков (§104, §105, §119)

**Инциденты-основания.** Polymarket (25.06.2026, ~$2,94 млн) — скомпрометированный вендор внедрил
скрипт, выманивавший одобрения. BONKfun (11.03.2026) — перевод домена через поддержку
DNS-провайдера. DarkSword (март 2026) — цепочка из шести уязвимостей iOS через заражённые сайты,
стилер искал данные кошельков, включая Phantom.

| Правило | Как проверяем |
| --- | --- |
| Лендинг и любые страницы рядом с кошельком — полностью same-origin: ни одного внешнего скрипта, фрейма, `eval`, `document.write`; строгий CSP; хэши отдаваемого бандла зафиксированы | `$ python3 scripts/check_landing_integrity.py --self-test && python3 scripts/check_landing_integrity.py` |
| Домен: registry/transfer lock, отдельная парольная фраза для поддержки регистратора, 2FA аппаратным ключом, мониторинг NS/WHOIS, заранее зарегистрированный резервный домен | ручное, чек-лист релиза |
| Контакты с командами кошельков и блок-листов прописаны заранее, чтобы фишинговый домен пометили быстро | `docs/INCIDENT_RESPONSE.md` §6 |
| Игра никогда не просит seed-фразу и не просит «подтвердить» что-либо в кошельке вне игры; фронтенд показывает игроку понятный состав инструкций и не отправляет неожиданные `SetAuthority`/`Assign`/`Approve`/durable-nonce | `onchain/test/client_policy.test.ts` (source-level гейт) |
| Напоминание игрокам обновлять ОС; для крупных сумм — аппаратный кошелёк с clear signing | комьюнити-политика |

## 4. Криптография, ключи и казна (§98, §101, §120–122, §126)

**Инциденты-основания.** Resolv (22.03.2026, $25 млн) — скомпрометированы ключи AWS KMS:
депозит $100 тыс. превратился в выпуск 50 млн USR. Step Finance (31.01.2026) — устройства
руководителей, 261 854 SOL, закрытие продуктов. Dominion Market (11.09.2026) — казначейский
мультисиг 3-из-5. Fogo Foundation (29.08.2026) — 400 млн FOGO с «горячего» ключа аллокаций.

| Правило | Как проверяем |
| --- | --- |
| Решение подписанта ограничено **ончейн** (инвариант выпуска, лимиты, caps) независимо от того, кто держит ключ; KMS — не панацея | `checked_*`, caps и `pause` в `onchain/programs/*`; тесты `onchain/test/security_*.test.ts` |
| Выводы проходят независимый policy-движок: allowlist получателей, лимит на транзакцию, лимиты скорости **суммарно по всем сетям**, обязательная задержка и двойное одобрение выше порога | `backend/src/tx_policy.ts` + `backend/scripts/transfer_preflight.ts` (гейт перед мультисигом) |
| «Что видит человек» = «что подписывается»: независимый декодер, сверка хэша интента, запрет лишних инструкций | `evaluateTransferBatch` (`decoder-mismatch`, `signed-hash-mismatch`), `assertSerializedMatchesBatch` |
| Горячий/тёплый кошелёк — жёсткий лимит остатка; излишек выметается на холодный мультисиг | `limits.warmWalletCapMicro` |
| Аллокации команды/фонда — в on-chain vesting с ограничением высвобождения за период, чтобы один ключ не сдвинул всё | правила программы/деплой-политики |
| После любого инцидента — «зачистка класса»: тот же баг ищут во всех старых версиях, форках и заброшенных компонентах; неактивный компонент не считается безопасным | `docs/DEPLOYMENT_POLICY.md` + чек-лист §5 ниже |

## 5. Реакция и восстановление (§110, §113, §128, §129)

**Инциденты-основания.** Volo (22.04.2026) заморозил $500 тыс. за 30 минут; Gnosis Pay
(01.06.2026) — тайм-делей обошли через ошибку проверки подписи; Liquid Network (06.09.2026,
~$320 млн) — исправление уязвимости попало в ветки, но не в релиз, а ПО федерации не обновлялось
годами; Aztec и Transit Finance получили повторные удары по «сестринским»/старым компонентам.

* **Предохранители тестируются состязательно** и по времени: учения «пауза» с замером
  времени до заморозки (цель SEV-1 < 15 минут) — раз в квартал, с записью в журнал.
* **Исправление уязвимости сначала деплоится, потом публикуется.** Публичный diff — готовая
  инструкция для атакующего (в том числе ИИ-агента).
* **Апстрим и форки:** подписка на security-релизы зависимостей; реестр всех задеплоенных
  программ с версиями, authority и статусом (активна/депрекейтнута/осушена);
  депрекейтнутые программы осушаются и закрываются, а не «забываются».
* **Набор для инцидента** (контакты, шаблоны, safe harbor, предавторизованная пауза) —
  `docs/INCIDENT_RESPONSE.md` §6 и `onchain/scripts/safe_harbor_memo.ts`.
