# Оригинальные карты: первый маршрут «Разогрев»

## Статус

Добавлен **прототип для проверки прохождения**, не готовый релизный уровень:
`data/maps/Neon Relay Warmup.map` (176 × 48 клеток), версия `warmup-test-2`.
Посадочные острова расширены: первые два до 12 клеток, третий до 14.
Это результат проверки физики, а не случайная перестройка маршрута.
Идентификатор проекта — `warmup`; имя сервера — `Neon Relay Warmup`;
русское название — «Разогрев». Режим — одиночная тренировка.

Это отдельная карта, не изменение LearnToPlay, Sound или Heights.
Персонажи, эффекты оружия, меню и платёжная логика не изменены.
Карточка локального тренировочного запуска теперь подключена (см. последний раздел). Названия турниров и их
тарифы не заменяются названиями трасс. «Басовая линия» и «Перегрев» пока
остаются проектами, их файлов нет.

## Что реализовано

- Авторская фиксированная геометрия: площадка старта, ступенчатый подъём,
  три прыжка между платформами, балка для крюка с нижними страховочными
  площадками, спуск и финишная прямая.
- Настоящие Game-тайлы: spawn 192, start 33, finish 34.
  Старт и финиш проходят через всю свободную высоту своих колонок:
  их нельзя просто перепрыгнуть сверху.
- Три контрольные точки: Tele 29 и выходы 30. Масляные ямы содержат
  Tele 63 — возврат к последней пройденной точке с погашением скорости.
  Это возврат, не ожог с уроном и не заморозка.
- `sv_solo_server 1`: маршрут не требует взаимодействия с напарником.
- Основные платформы — no-hook; отдельная верхняя балка — hookable.
  Балка предназначена для тренировки, **обязательное использование крюка
  не гарантируется**: опытный игрок может искать обход двойным прыжком.
- Существующий собственный фиолетовый материал Sound, пиктограммы,
  атмосферная текстура и 16 кадров кипящего масла встроены в файл.
  Положение твёрдых границ неподвижно. Двигаются пики музыкальных индикаторов
  и фоновые волны; масло использует покадровые огибающие с циклом 1,28 секунды.

## Происхождение и инструмент

`scripts/build_warmup.py` создаёт пустую DDNet06-карту через **twmap 0.6.6**.
Ни один существующий `.map` не читается и геометрия чужих карт не копируется.

Встроены без перерисовки четыре собственных PNG:

- `neonrelay_learn_terrain.png`, `neonrelay_learn_symbols.png`,
  `neonrelay_learn_atmosphere.png` — исходники в `scripts/learn_visibility.py`;
- `neonrelay_learn_oil.png` — исходник в `scripts/learn_oil.py`.

Префикс `learn` обозначает историю наших текстур, а не заимствование
геометрии LearnToPlay. Метаданные карты и запись asset manifest указывают
The Neon Relay Authors / Zlib. Лицензии движка, библиотеки twmap и остальных
компонентов сохраняются; «своя карта» не отменяет эти обязательства.

## Воспроизведение и проверки

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r scripts/requirements-assets.txt -r scripts/requirements-map-tools.txt
.venv/bin/python scripts/build_warmup.py
.venv/bin/python scripts/test_warmup.py
```

Пять структурных тестов проверяют DATA v4, побайтовую воспроизводимость,
независимые Game/Tele-записи, безопасное размещение выходов, соответствие
видимого материала коллизиям, анимацию и SHA-256 карты в отчёте физики.

### Исполняемая проверка физики

```sh
# Linux, Python 3 и g++; полная сборка клиента/Rust/SDL не требуется.
python3 scripts/test_warmup_physics.py --sanitize --report /tmp/warmup-core.json
```

Стенд компилирует **неизменённые** `CCharacterCore`, `CCollision`, `CLayers`,
`CTeamsCore`, PRNG и память из движка. Независимый DATA-reader экспортирует
Game/Tele из сохранённой карты; небольшой IMap-адаптер предоставляет эти
записи движку. Своей формулы прыжков/хука здесь нет. Отдельно реализованы
только подача ввода, тестовое хранилище конфигурации и вывод ошибок.

Результат `docs/WARMUP_PHYSICS_PROBE.json` привязан к SHA-256 текущего файла:

| Проверка | Результат |
|---|---|
| Непрерывное движение от spawn до финишного тайла | 1031 такт, 9 прыжков с земли, 10 зацепов |
| Контакт со стартом, финишем и колонками трёх checkpoint | Подтверждён кодом Collision |
| Первые три острова без торможения в воздухе, двойного прыжка и крюка | Посадка на третий остров за 324 такта |
| Падение в каждую из шести ям | Достигнут нативный триггер Tele 63 |
| Все три выхода checkpoint | Персонаж устойчиво приземляется на пол |
| No-hook материал | Зацеп отвергнут |
| Два перекрывающихся solo-персонажа | Не выталкивают друг друга |
| Отрицательный контроль: балка заменена на no-hook | Проверка зацепа действительно падает |
| Отрицательный контроль: финиш удалён | Проверка достижения финиша действительно падает |
| AddressSanitizer + UndefinedBehaviorSanitizer | Проверка прошла, остановка при ошибке включена |

В основном прогоне бот регулирует направление и прыжки, **не меняет
позицию/скорость** и не применяет super/endless-hook. Отдельные проверки
ям и выходов начинают с заданной тестовой позиции; они не выдаются за
непрерывное прохождение.

**Границы доказательства:** это исполняемый тест физического ядра, а не
полный `CCharacter` на сервере. Контакт с финишным тайлом не доказывает запись
результата гонки. Обнаружение Tele 63 и безопасного выхода не доказывает
выполнение серверного переноса между ними. Solo включён в тестовых ядрах;
обработка сервером соответствующей настройки карты здесь не проверяется.
Ручного прохождения в клиенте пока нет. Эти ограничения явно записаны в JSON.

## Запуск на Mac — два терминала

Обновить рабочую копию:

```sh
cd "$HOME/neon-relay-mac-preview"
git pull --ff-only origin arena/01a0b21c-neon-relay
```

Терминал 1 — отдельный локальный сервер на порту 8305:

```sh
cd "$HOME/neon-relay-mac-preview"
./build-mac/neonrelay-server \
  "bindaddr 127.0.0.1" "sv_port 8305" "sv_register 0" \
  'sv_map "Neon Relay Warmup"'
```

Терминал 2 — клиент:

```sh
cd "$HOME/neon-relay-mac-preview"
./build-mac/neonrelay \
  "gfx_fullscreen 0" "gfx_screen_width 1200" "gfx_screen_height 760" \
  "cl_show_welcome 0" "connect 127.0.0.1:8305"
```

Используются ранее собранные бинарники; изменение только карты не требует
пересборки C++. Команды приведены для локального Mac, не для браузерного
preview. Выполнение именно на Mac в этой сессии не проверялось.

## Полный серверный сценарий (добавлен после версии 2)

`scripts/test_warmup_server.py` запускает настоящий клиент и сервер в отдельной
временной директории, без регистрации сервера и без доступа к рабочей БД.
`tests/warmup/server_probe.cpp` подаёт обычные player inputs перед тиком мира.
Он не записывает координаты/скорость персонажа, состояние гонки или таймер.
После первого финиша используется обычное убийство/возрождение игрока;
затем игрок намеренно падает в каждую из шести ям и финиширует снова.
Обработчики `CCharacter`, teams и score остаются неизменёнными.

Проверяются STARTED/FINISHED, новое время старта после возрождения, сохранение
таймера при возврате, номер последнего checkpoint, погашение скорости,
встроенная solo-настройка карты и **две записи положительного времени в
изолированной SQLite-БД**. Результат пишет `warmup-server-proof.json` в
артефакт `native-client-preview`; лог очищается от строк с паролями.

Драйвер компилируется только при `-DNEONRELAY_WARMUP_PROBE=ON` (по умолчанию
OFF), активируется только переменной `NEONRELAY_WARMUP_PROBE=1` и отказывает
при публичной привязке/регистрации, иной карте, ином имени клиента или
включённых чит-командах. **Такой инструментированный сервер нельзя поставлять
игрокам.** Обычная серверная CI-сборка остаётся с опцией OFF; клиентский CI
включает её только для тестов, бинарник в артефакты не публикуется.

Сценарий включён в `scripts/test_native_client.sh`. Локально успешно выполнены syntax-check обоих вариантов gamecontext,
два offline-теста обёртки и полный локальный CI.

**Полный серверный сценарий прошёл** в коммите `8109918`:
[CI 35437619097](https://github.com/Leo88q/neon-relay/actions/runs/35437619097),
все 7 заданий — success. Клиентское задание не может завершиться успешно без
двух финишей, шести серверных возвратов и двух записей времени в SQLite.

`docs/WARMUP_SERVER_CI.json` сохраняет проверенные через GitHub API статусы,
коммит, SHA-256 неизменённой карты и список проверяемых условий. Это квитанция
о результате CI, **не копия runtime JSON**. Последний вместе со скриншотами
остался в артефакте: загрузка снова завершилась EOF, поэтому конкретные
значения времени здесь не переписываются и ручной просмотр не заявляется.
Ограничения `WARMUP_PHYSICS_PROBE.json` относятся к отдельному тесту ядра;
они не были задним числом изменены на серверные доказательства.

Ручного клиентского прохождения этот автоматизированный тест не заменяет.
Карточка лобби добавлена позднее, см. ниже; остальные две оригинальные карты
пока не созданы. Персонажи, LearnToPlay/Sound/Heights и платёжная логика не изменены.

## Карточка «Разогрев» в лобби

В разделе **Забеги** появилась отдельная бесплатная тренировочная карточка
перед платными категориями. Она одинакова на вкладках SKR/POTATO и не вызывает
кошелёк. Кнопка **«Начать „Разогрев“»** запускает встроенный механизм локального
сервера на `127.0.0.1:8305` с точным именем карты и подключает клиент.

- `practice_course.h` фиксирует ID `warmup`, имя, путь и SHA-256 проверенной
  версии 2; тест сверяет fingerprint с файлом карты.
- Проверка файла выполняется до запуска; при отсутствии/другой версии нужно
  обновить данные. После загрузки повторно проверяются имя и SHA-256 карты.
- Занятый порт, активное подключение или уже запущенный управляемый сервер
  приводят к отказу с сообщением; чужой процесс не завершается.
- Локальный сервер не регистрируется, имеет временный пароль, не использует
  MySQL, пишет только в `warmup-practice.sqlite`. Подписание наград выключено.
  Тренировка не выдаёт рейтинговые призы.
- После отключения в карточке доступна кнопка **«Остановить тренировочный
  сервер»**. Она завершает только запущенный этой карточкой процесс. После
  остановки снова доступен запуск. Выход из клиента также завершает его сервер.
- Контекст перевода `Original course` сохраняет название «Разогрев», не меняя
  старый игровой термин Warmup → «Разминка».

На Mac для новой кнопки нужна пересборка клиента (не только обновление карты):

```sh
cd "$HOME/neon-relay-mac-preview"
git pull --ff-only origin arena/01a0b21c-neon-relay
cmake -S . -B build-mac -DCLIENT=ON -DSERVER=ON -DNEONRELAY_WARMUP_PROBE=OFF
cmake --build build-mac --target game-client game-server --parallel 2
./build-mac/neonrelay "cl_show_welcome 0"
```

Затем: **Забеги → Разогрев → Начать**. Отдельный терминал сервера не нужен.
Если на 8305 ещё работает сервер из предыдущей инструкции, сначала остановите
его либо подключитесь к нему через список серверов.

Локально прошли 10 контрактных тестов меню, syntax-check включая local_server,
и полный `ci-local.sh`. В native CI добавлен `test_warmup_lobby.py`: реальные
клики, отказ при занятом порте, проверенный вход, остановка, повторный вход
и освобождение порта после выхода. Сценарий прошёл на commit `dec3ebe`; подтверждение —
`docs/WARMUP_LOBBY_CI.json`. Mac/Android этим Linux-тестом не считаются проверенными.

Дополнение к проверке карточки: «Разогрев» явно включён в CMake EXPECTED_DATA
и в `data/maps/license.txt`. Native-тест теперь использует **собранный каталог
build/data**, а не данные исходного checkout. Это защищает от ситуации, когда
кнопка работает у разработчика, но в сборке нет карты. Тестовые клики учитывают
виртуальный относительный курсор и задают ui_mousesens=100 только в одноразовом
профиле CI; пользовательская чувствительность не изменяется.
Первый прогон d090e04 не прошёл клиентское задание; диагностический вывод CI
исправлен так, чтобы traceback основного сценария не вытесняли старые логи.

Нативный прогон d5ca2a6 подтвердил попадание клика в кнопку и отказ при занятом
порте, затем обнаружил реальную ошибку общего launcher: PLAT_SERVER_EXEC всё
ещё разворачивался в старое upstream-имя, а CMake собирает `neonrelay-server`.
Общие имена клиента/сервера в updater.h согласованы с CMake; этот заголовок
используют также storage и local_server при выключенном AUTOUPDATE. Автообновление
остаётся выключенным. Контрактный тест теперь проверяет согласованность имён.

Следующий прогон d066a9b уже прошёл первый запуск, проверку имени/SHA карты,
вход игрока и остановку сервера. Повторный запуск обнаружил подмену нового
явного пароля старым сохранённым при совпадении адреса. В CClient::Connect
явный пароль теперь имеет приоритет; обычное переподключение без явного
пароля сохраняет прежнее поведение. Повторный полный сценарий прошёл.
