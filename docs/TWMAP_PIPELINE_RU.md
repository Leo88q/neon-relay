# Проверенный ввод/вывод карт через twmap

## Что действительно подключено

Используются Python-биндинги **twmap 0.6.6**, а не отдельная Go-реализация с похожим
именем. Rust/Go SDK для этого опыта не устанавливались: использован готовый
бинарный wheel PyPI. В опубликованных файлах 0.6.6 есть также CPython abi3 wheels
для macOS x86_64 и arm64. Установка на Mac здесь не проверялась.

- Пакет/версия: https://pypi.org/project/twmap/0.6.6/
- Репозиторий, указанный в метаданных пакета: https://gitlab.com/Patiga/twmap-py
- Rust API: https://docs.rs/twmap/
- Отдельная Go-реализация: https://pkg.go.dev/github.com/jxsl13/twmap
  (в этом изменении не установлена и не проверена; её API не смешивается с Rust/Python).

Реальные сигнатуры дополнительно проверены через `help()` установленного модуля:

```python
m = twmap.Map.empty('DDNet06')
group = m.groups.new_physics()
game = group.layers.new_game(32, 16)
group.layers.new_physics('Front')
m.save(str(path))
```

Это подтверждённый API, не псевдокод вымышленного генератора. Вспомогательный
модуль — `scripts/twmap_pipeline.py`. Три пользовательские карты пока не создавались.

## Лицензия инструмента

У установленного Python-пакета поле License — **AGPL-3.0-only**. Это не MIT.
Зависимость выделена в `requirements-map-tools.txt` как инструмент разработки;
она не добавляется в CMake, клиент, сервер, приложение Android или игровой runtime.
Это не юридическое заключение о любой возможной схеме распространения/интеграции.
Перед расширением применения нужно учесть условия лицензии инструмента. Применение
библиотеки само по себе не разрешает копировать геометрию/изображения чужих карт.

Технический fixture создан с нуля без сторонних карт и изображений. Его map.info
обозначен CC0-1.0; это относится к нашему fixture, не переопределяет лицензию twmap.

## Что проверено

Для `LearnToPlay`, `LearnToPlay Sound`, `LearnToPlay Sound Heights` выполнено:
чтение библиотекой → запись **во временный файл** → повторное чтение.

1. Совпадают numpy-массивы всех имеющихся игровых слоёв, их форма/тип и настройки.
2. Независимый от twmap `map_gameplay_fingerprint.py` подтверждает совпадение
   сериализованных игровых данных и настроек.
3. Хэш исходного файла не изменяется. Карты из `data/maps` никогда не перезаписываются.
4. Отдельный оригинальный fixture проверяет Game, Front, Tele, Speedup, Switch,
   Tune, старт/финиш/спавн, заморозку, флаг поворота, номера телепортов,
   направление ускорителя, задержку переключателя и настройку tune-зоны.
   Его сырые записи сверены с layout из `src/game/mapitems.h`.
5. Неверный входной файл отвергается, неподдержанная версия пакета не принимается.

Отчёт запуска: `docs/TWMAP_PROBE.json`. Fixture — только техническая проверка,
без графического оформления; это не готовая трасса и не доказательство проходимости.

## Реально обнаруженный нюанс Speedup в 0.6.6

Чтение `layer.tiles` даёт `[force, max_speed, id, angle]`, как описано в help().
Но setter этой версии принимает `[id, force, max_speed, angle]`. Прямая запись
прочитанного массива обратно меняет значения местами.

Поэтому `assign_tiles()` для Speedup переставляет колонки **всего массива** перед
записью. Остальные слои не переставляются. Проверка read-modify-write меняет
силу одного ускорителя и требует сохранения всех остальных значений. У fixture
сырая запись ускорителя обязана быть `0a 14 1c 00 b4 00`: force 10, max_speed 20,
id 28, padding 0, angle 180. Наивная запись дала `14 1c 0a 00 b4 00` и была поймана
независимым тестом. Адаптер привязан строго к 0.6.6; обновление версии требует тестов.

## Что пока НЕ доказано

- Побайтовая идентичность всего файла не гарантируется.
- У двух Sound-производных число элементов расширения типа 65534 после записи
  меняется с 22 на 11. Это зафиксированное изменение контейнера; оно само по себе
  ещё не доказывает потерю игровой механики, но запрещает обещать полное сохранение
  всех расширений. Причину и визуальные последствия нужно проверить отдельно.
- Визуальная эквивалентность, сохранение любых неизвестных расширений и нативный
  запуск именно пересохранённых файлов пока не проверены.
- Нативный редактор, генераторы изображений, графика трёх трасс и связь новых карт
  с лобби этим изменением не реализуются.

**Старые генераторы не переключены автоматически на новый writer.** Для новых
оригинальных карт проверена возможность начать с пустого `DDNet06`; миграция
старых файлов потребует дополнительных проверок изображений, envelopes и расширений.

## Повторить опыт

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r scripts/requirements-map-tools.txt
.venv/bin/python scripts/test_twmap_pipeline.py
.venv/bin/python scripts/twmap_pipeline.py --report /tmp/twmap-probe.json
```

Для полного локального CI нужны также `scripts/requirements-assets.txt` и обычные
зависимости проекта. Проверки twmap включены в `ci-local.sh` и профильный CI-job;
это обязательные тесты, а не silently-skipped проверки при отсутствии пакета.
